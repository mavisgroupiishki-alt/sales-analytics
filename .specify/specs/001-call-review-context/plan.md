# Технический план: Проверка звонков и контекст сделки

**Спека:** [spec.md](spec.md)  
**Создан:** 2026-09-28

## Технологии

Существующие Flask, server-rendered HTML/CSS, private Jarvis PostgreSQL и Python-процесс анализа. Новые клиентские зависимости не требуются.

## Архитектура

```text
Операционный дашборд
  └─ signed iframe session → Jarvis Flask
       ├─ журнал / фильтры / очередь РОПа
       ├─ ручная проверка → private Postgres review record
       └─ точечный reanalysis → worker
                                  ├─ CRM snapshot текущей сделки
                                  ├─ <= 8 summaries прошлых звонков сделки
                                  └─ immutable analysis + context snapshot
```

## Схема данных

- `jarvis.call_reviews`: `call_id`, выбранный тип, причина, автор, время, опциональная ручная оценка, флаг запроса на повторный анализ. Одна актуальная проверка на звонок с историей событий либо отдельной журнальной записью.
- `jarvis.call_analyses.result`: снимок использованного контекста: количество, IDs и краткие факты прошлых звонков. Он неизменяем вместе с версией анализа.
- JSON fallback хранит тот же контракт ручной проверки в `manual_corrections.json`, не сокращая поля до одного балла.

## API / интерфейсы

- Подписанная роль `dashboard` допускается к read-only вкладкам и действиям проверки, доступным РОПу; менеджерские ограничения не расширяются.
- `POST /calls/<id>/review`: валидирует тип, причину, автора; сохраняет ручное решение.
- `POST /calls/<id>/reanalyze`: сохраняет запрос и запускает только этот ID.
- `/calls`: принимает параметры фильтра и сохраняет их в URL.
- Карточка звонка показывает блок проверки, контекст и историю использованных звонков.

## Зависимости

1. Сначала контракты хранения и роль встроенной сессии.
2. Затем сбор и сохранение контекста в анализаторе.
3. После этого UI проверки, фильтры и очередь.
4. В конце — сохранение iframe при обновлении основного дашборда.

## Риски

- В истории может не быть связанной сделки: тогда анализ явно работает без исторического контекста.
- Повторный анализ может быть дорогим: он запускается только явным действием для одного ID.
- База и JSON fallback могут расходиться: контракт обзора реализуется в обоих путях и покрывается тестами.

## Проверка конституции

- [ ] Источник, версия и ручное решение показываются раздельно.
- [ ] Длина контекста ограничена восемью звонками и не содержит архивных транскриптов.
- [ ] Фоновое обновление не разрушает активный рабочий экран.
- [ ] Секреты и записи остаются на сервере.
