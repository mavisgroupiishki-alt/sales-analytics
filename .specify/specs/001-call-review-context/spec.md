# Спецификация: Проверка звонков и контекст сделки

**ID:** 001-call-review-context  
**Статус:** Approved  
**Создана:** 2026-09-28

## Цель

Сделать журнал звонков устойчивым рабочим местом РОПа: с ручным подтверждением типа, понятной очередью решений, фильтрами и корректной AI-оценкой с историей сделки.

## Пользовательские истории

- Как руководитель, я хочу открыть все рабочие вкладки Jarvis внутри операционного дашборда, чтобы не получать 403 и не входить повторно.
- Как руководитель, я хочу вручную подтвердить или исправить тип звонка и указать причину ошибки, чтобы отчёты отражали проверенное решение.
- Как руководитель, я хочу видеть очередь звонков, требующих решения, чтобы не пропускать неопределённые, неуверенные и ошибочные разборы.
- Как руководитель, я хочу фильтровать звонки по ответственному, типу, стадии, баллу и наличию анализа, чтобы быстро находить нужные разговоры.
- Как руководитель, я хочу, чтобы оценка текущего звонка учитывала историю до восьми предыдущих звонков одной сделки, чтобы рекомендации не противоречили уже достигнутым договорённостям.
- Как руководитель, я хочу видеть, какие прошлые разговоры ИИ использовал как контекст, чтобы понимать основания оценки.
- Как руководитель, я хочу видеть отчёт расхождений ИИ и ручных решений с моими причинами, чтобы улучшать правила и модель на реальных ошибках.

## Функциональные требования

1. Подписанный вход из операционного дашборда ДОЛЖЕН открывать вкладки «Воронка», «Команда», «Отчёты менеджеров», «Отчёт РОПа» и «Скрипты» без 403; прямой неавторизованный доступ ДОЛЖЕН оставаться закрытым.
2. Обновление основного дашборда ДОЛЖНО сохранять открытую страницу Jarvis, выбранный период, фильтры, прокрутку и незавершённые правки.
3. Карточка звонка ДОЛЖНА позволять уполномоченному пользователю выбрать подтверждённый тип, написать причину исправления и сохранить автора и дату проверки.
4. Ручной тип ДОЛЖЕН иметь приоритет над AI-типом во всех списках, фильтрах и отчётах, но исходный результат ИИ ДОЛЖЕН быть доступен для сравнения.
5. Пользователь ДОЛЖЕН иметь выбор между «сохранить тип» и «сохранить и переоценить». Повторный анализ ДОЛЖЕН выполняться только для выбранного звонка.
6. Журнал звонков ДОЛЖЕН поддерживать фильтры: ответственный, тип звонка, стадия сделки, диапазон баллов и состояние анализа (с анализом, без анализа, ожидает, ошибка, требуется проверка).
7. Очередь «Нужно решение РОПа» ДОЛЖНА включать неподтверждённые типы, низкую уверенность анализа и ошибки/отсутствие анализа; подтверждённые вручную записи ДОЛЖНЫ исчезать из неё, если иных причин нет.
8. Перед анализом ДОЛЖЕН собираться контекст: текущая стадия, ответственный и доступные ключевые CRM-поля, а также максимум восемь предыдущих звонков той же сделки.
9. Для каждого предыдущего звонка в контексте ДОЛЖНЫ использоваться дата, подтверждённый или AI-тип, резюме, возражения, договорённости и следующий шаг. Полные старые транскрипты в контекст не передаются.
10. Текущий анализ ДОЛЖЕН явно содержать список использованных предыдущих звонков и их количество; интерфейс ДОЛЖЕН показывать индикатор и раскрываемую историю.
11. Отчёт расхождений ДОЛЖЕН показывать AI-тип/балл, ручной тип/балл, автора, дату и написанную руководителем причину. Эти записи ДОЛЖНЫ быть доступны для последующей калибровки, но не менять модель автоматически без отдельного решения.

## Вне скоупа

- Автоматическое дообучение внешней модели без контроля человека.
- Полная загрузка архивных транскриптов в каждый AI-запрос.
- Изменение данных сделки в Bitrix24 из Jarvis.

## Критерии приёмки

- [ ] Встроенная сессия дашборда получает 200 на все требуемые рабочие вкладки; неавторизованная — нет.
- [ ] Фоновое обновление операционного дашборда не перезагружает iframe звонков.
- [ ] Ручное исправление типа остаётся после обновления страницы и после нового анализа.
- [ ] Все пять групп фильтров одновременно сужают журнал звонков корректно.
- [ ] Контекст содержит не более восьми более ранних звонков только связанной сделки и показывает их количество пользователю.
- [ ] В отчёте калибровки присутствует введённая причина ручной ошибки.
