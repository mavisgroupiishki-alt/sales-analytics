# Технический план: Память контекста компании

**Спека:** [spec.md](spec.md)
**Создан:** 2026-10-05

## Технологии

Существующие Python, Flask, private schema `jarvis` в Supabase/Postgres и live-worker Render. Новых внешних сервисов и моделей не требуется.

## Архитектура

```text
Новый звонок Bitrix
  └─ Vibe transcription + анализ только этого звонка
       └─ JarvisStore
            ├─ context_facts: краткий, доказуемый факт звонка
            │    └─ company/contact/deal + funnel + source call/analysis
            └─ context_profiles: актуальный срез каждой CRM-связи

Следующий звонок
  └─ read_context_for_call()
       ├─ текущая сделка, контакт, компания в той же воронке
       ├─ актуальный срез
       └─ <= 8 последних фактов → prompt
```

## Схема данных

- `jarvis.context_facts`: актуальный краткий факт анализа одного звонка для одной CRM-связи и воронки. Уникальность на `(call_id, scope_type, scope_external_id, funnel_id)` не даёт старой версии анализа остаться в памяти.
- `jarvis.context_profiles`: материализованный срез этой связи: счётчик фактов, дата последнего звонка, последний исход и следующий шаг.
- Связи строятся только из явных Bitrix `deal`, `contact`, `company`; ключ компании предпочтительнее для общего контекста, а контакт/сделка сохраняют точность без компании.

## API / интерфейсы

- Нового публичного endpoint не требуется.
- `JarvisRepository.load_context_for_call(call_meta)` возвращает готовый фактологический контекст для модели.
- `JarvisStore.write_analysis_snapshot()` обновляет факты и срез после записи нового анализа.
- `JarvisRepository.save_call_review()` синхронизирует вручную подтверждённый тип с фактами.

## Зависимости

1. Миграция создаёт приватные таблицы и однократно заполняет факты из существующих анализов.
2. Хранилище записывает и читает контекстные факты.
3. Анализатор читает память прежде обращения к историческим записям Bitrix.
4. Тесты проверяют границы и изоляцию.

## Риски

- CRM может не дать компанию: используется явный контакт или сделка в известной воронке; если у связанной активности нет идентификатора воронки, общий факт не сохраняется, чтобы не смешать несколько воронок одной компании. Нечёткое сопоставление не выполняется.
- Старые факты могут содержать устаревший следующий шаг: срез всегда показывает дату источника, а текущая CRM-стадия остаётся отдельным фактом.
- Один большой prompt ухудшит скорость и точность: весь архив остаётся в базе, но модели передаётся не более восьми фактов.

## Проверка конституции

- [ ] Все факты содержат источник и дату.
- [ ] Prompt ограничен восемью фактами и не содержит архивных транскриптов.
- [ ] Ручное решение имеет приоритет и обновляет память.
- [ ] Таблицы остаются в private schema с RLS и без прав для public.
