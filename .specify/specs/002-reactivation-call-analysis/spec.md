# Спецификация: Полный анализ звонков реанимации

**ID:** 002-reactivation-call-analysis
**Статус:** Approved
**Создана:** 2026-10-02

## Цель

Очередь «Реанимируем реанимацию» должна сама анализировать все доступные записи звонков, непосредственно привязанные к каждой открытой сделке в воронке «Реанимация», и принимать рекомендацию по их полному контексту, комментариям и полям CRM.

## Пользовательские истории

- Как РОП, я хочу видеть готовую рекомендацию в очереди реанимации, не переходя в отдельный интерфейс Jarvis.
- Как РОП, я хочу, чтобы система сама разобрала исторические звонки каждой сделки реанимации, чтобы решение не строилось только по комментарию или дате активности.
- Как РОП, я хочу видеть в карточке сделки, какие звонки были учтены и какие невозможно разобрать из-за отсутствующей записи.

## Функциональные требования

1. Система ДОЛЖНА получать из Bitrix всю историю завершённых звонков, непосредственно связанных с каждой открытой сделкой в воронке «Реанимация».
2. Система ДОЛЖНА анализировать каждую доступную аудиозапись, для которой ещё нет сохранённого анализа, и постоянно сохранять результат как самостоятельный анализ Jarvis.
3. Звонки без доступной записи ДОЛЖНЫ быть явно отражены как недоступные для прослушивания, но не должны получать фиктивный анализ.
4. Финальная рекомендация ДОЛЖНА учитывать результаты всех подготовленных звонков, комментарии и поля сделки; в один запрос модели передаются только краткие факты максимум восьми последних релевантных разговоров.
5. Карточка рекомендации ДОЛЖНА показывать количество всех звонков сделки, число разобранных ИИ и число записей без разбора с причиной.
6. Очередь и её карточки ДОЛЖНЫ оставаться рабочими без открытия отдельной страницы Jarvis.
7. Автоматический перенос сделки в продажи не выполняется: перенос остаётся отдельным явным действием РОПа «Реанимировали → Новая».

## Вне скоупа

- Поиск звонков через связи компании или контакта: в этот контур входят только звонки, напрямую привязанные к сделке.
- Повторный анализ уже сохранённого результата без явной причины.
- Имитация анализа для звонков без воспроизводимой записи.

## Критерии приёмки

- [ ] Для сделки с несколькими историческими звонками очередь показывает их количество и использует их результаты при рекомендации.
- [ ] Два последовательных запуска не создают повторного анализа уже разобранного звонка.
- [ ] Звонок без записи виден в счётчике, но не выдаётся за проанализированный ИИ.
- [ ] Контекст финальной рекомендации не превышает восемь кратких резюме и не содержит старых полных расшифровок.
